# LiveMark桥接协议

原生 AppKit 进程与 WebKernel 通过 WKWebView 交换 JSON 消息。协议版本字段为 `__livemark`，当前值为 `1`。

## 1. 通道

| 方向 | 调用入口 |
|---|---|
| WebKernel → 原生 | `window.webkit.messageHandlers.livemark.postMessage(envelope)` |
| 原生 → WebKernel | 通过 WKWebView 执行 `window.__livemark.dispatch(envelope)` |

## 2. 消息格式

| 类型 | 字段 | 行为 |
|---|---|---|
| `call` | `id`、`handler`、`data` | 请求对方执行操作并返回结果。 |
| `response` | `id`、`ok`，以及可选的 `data` 或 `error` | 使用与请求相同的 `id`。 |
| `event` | `name`、`data` | 通知状态变化，无需回执。 |

例如，原生端可发出如下请求，让 WebKernel 返回当前的 Markdown 内容。

```json
{
  "__livemark": 1,
  "type": "call",
  "id": "n-1",
  "handler": "file.save",
  "data": {}
}
```

原生端请求 ID 以 `n-` 开头，WebKernel 请求 ID 以 `j-` 开头。所有请求均为异步调用，双方通过 ID 匹配响应。

## 3. 常用处理器

### 3.1 应用

`app.ready` 通知原生端 WebKernel 已就绪。`app.echo` 可检查双向通信。`app.setTheme` 和 `app.setFont` 将应用设置同步到编辑器。

### 3.2 文件

`file.read` 载入文档，`file.save` 返回当前 Markdown，`file.status` 返回文档状态。WebKernel 用 `file.readAck` 确认文档已载入。

### 3.3 窗口

WebKernel 可以通过 `window.setTitle` 更新标题，通过 `window.setDirty` 更新未保存标记，以及通过 `window.showDialog` 请求系统对话框。

## 4. 启动和文档更新

1. 原生端创建 WKWebView，注册消息通道并加载 WebKernel。
2. WebKernel 安装处理器后发出 `app.ready`，原生端随后发送排队中的消息。
3. 原生端通过 `file.read` 载入文档。WebKernel 通过 `file.readAck` 确认收到内容。
4. 外部文件变化时，原生端用 `file.reloadIfClean` 检查文档及保存基线。发生编辑冲突时，通过 `file.externalChange` 更新界面提示。

## 5. 实现

协议实现位于 [Swift 桥接代码](../app/Sources/LiveMark/Bridge/) 和 [TypeScript 桥接代码](../app/kernel-src/src/bridge.ts)。修改消息字段时需要同步更新两端。
